## Чому Vim++

Vim++ стартує за **однозначні мілісекунди** — весь редактор це один бінарник Rust; немає окремого процесу плагінного хоста, немає рукостискання з демоном, немає довгоного автозавантаження. Коли ти запускаєш `vimpp src/main.rs`, ти вже редагуєш тоді, коли Vim щойно закінчив читати свої runtime-скрипти.

При цьому ти не втрачаєш нічого з Neovim-воркфлоу: **модальне редагування, таби, `:`-команди і плагіни — скриптуються нативно в Lua всередині процесу редактора** (через [mlua](https://crates.io/crates/mlua)). Жодного RPC, жодного мосту, жодного лагу.

| | Vim++ | Vim | Neovim |
|---|---|---|---|
| Запуск | **~5–15 мс** | 30–150 мс | 40–300 мс |
| Скриптинг | Lua, в межах процесу | Vimscript | Lua через RPC |
| UI | ratatui (скрізь, без GPU) | curses | curses |
| Пам'ять у покої | ~10 МБ | ~10 МБ | ~30 МБ |

## Можливості

- **Модальне ядро** — Normal / Insert / Visual (символьний і рядковий) / Command, з `hjkl w b e 0 $ ^ G gg`, `x dd dw yy p P i a A o O I`, `J` (склейка рядків), `u` / `<C-r>` (undo на 300 кроків), `/пошук` + `n` / `N`.
- **Нумерація рядків** — за замовчуванням показуються звичайні номери; `:set relativenumber` перемикає інші рядки на відстань від курсора.
- **Таби → буфери**, `gt` / `gT`, `<C-n>` / `<C-p>`, `:b[!]`, `:bd`, `:bn`, `:bp`, `:e файл`.
- **Файловий оглядач** — `Ctrl-b` відкриває/фокусує; `j/k` навігація, `Enter`/`l` відкриває файли і провалюється в теки, `h` піднімається.
- **Підсвітка синтаксису** — вбудований lexer без зовнішніх залежностей: Rust, JS/TS, Python, C, Go, Lua, HTML, CSS, JSON, TOML, Markdown, SQL, YAML, Shell. Зміщення токенів говорять по-юнікодовому (літери, не байти!).
- **Автодоповнення слів** у Insert — попап зі слів буфера, `<Tab>` приймає, `<C-n>`/`<C-p>` гортає.
- **Попап доповнення команд** — `:set <Tab>` гортає `number`, `relativenumber`, `tabstop`, ...
- **Тема** — палітра Nordic; кольори можна перевизначити в `config.toml`. Для очікуваного вигляду оберіть у терміналі шрифт **JetBrains Mono**.
- **Довідка** — натисніть `[ HELP ]`, клавішу `F1` або введіть `:help`, щоб переглянути повний опис функцій і клавіш.
- **Нативні Lua-плагіни** — див. нижче.

## Швидкість запуску

`vimpp` міряє час від `main()` до першого кадру і показує його при виході:

```
⚡ Vim++ готовий — старт за 6.1 мс. NamASTE ✌
```

Немає плагінів на диску = немає плати за плагіни. Lua вендориться в бінарник; `Lua::new()` коштує мікросекунди.

## Встановлення

```sh
# збірка з джерел (Rust 1.78+)
git clone https://github.com/your-handle/vimpp && cd vimpp
cargo build --release
./target/release/vimpp src/main.rs
```

На Windows: `cargo build --release`, потім `target\release\vimpp.exe src\main.rs`.

## Клавіші (шпаргалка v0.2)

| Режим | Клавіші |
|---|---|
| Увійти в режими | `i`, `I`, `a`, `A`, `o`, `O`, `v`, `V`, `:`, `/` |
| Рухатися | `h j k l`, `w b e`, `0 $ ^`, `gg G`, стрілки |
| Редагувати | `x dd dw`, `y p P`, `J` (склеїти), `u <C-r>` |
| Visual | `v`/`V`, `d`, `y`, `c`, тип виділення міняється `v`/`V` |
| Пошук | `/текст⏎`, далі `n` / `N` |
| Буфери | `gt`, `gT`, `<C-n>`, `<C-p>`, `:bn`, `:bp`, `:b 2`, `:bd!` |
| Файли | `<C-b>` (оглядач), `:e шлях`, `:w [файл]`, `:wq`, `:x` |
| Опції | `:set number`, `:set nonumber`, `:set tabstop=2`, `:set expandtab!` |
| Доповнення | `<Tab>`, `<C-n>`, `<C-p>` (у Insert); `<Tab>` у рядку `:` |

## Нативні Lua-плагіни

Все, що ти щодня скриптуєш у Neovim, працює **в межах одного процесу**:

```lua
-- ~/.vimplus/init.lua
vimpp.echo("мій конфіг вантажиться…")

vimpp.keymap.set("n", "Y", "y$")            -- рядок = годівля клавіш
vimpp.keymap.set("n", "<C-t>", function()   -- функція = повертає дію
  return ":set nu!"                          -- ":команда" — виконати ex-команду
end)

vimpp.command("Greet", function(args)       -- своя власна ex-команда
  return "!Привіт, " .. (args or "світе")   -- "!текст" = повідомлення
end)

vim.cmd(":set relativenumber")              -> застосується після init.lua
vimpp.set_option("tabstop", 2)
```

**Протокол дій**: хендлер повертає `":ex-команду"`, `!"повідомлення"` або сиру
послідовність ключів (`"gg"`, `"iHello"`, `"<Esc>"`...). `nil` = "оброблено,
без дій". увага-помент: `vimpp.echo/set_option/exec` і `vim.cmd` у час завантаження
**буферизуються** і застосовуються одразу після повернення зі скрипта — плагіни
компонуються без реентрантного пекла. `vim.api.nvim_set_keymap`, `vim.o`, `vim.g`
зашимлені для знайомості.

Налаштування живуть у двох щасливих місцях:

```
~/.vimplus/config.toml   # сторона Rust: кольори теми, number/tabstop/expandtab
~/.vimplus/init.lua      # сторона Lua: мапи, команди, твої найсміливіші ідеї
```

## Архітектура

```
src/
├── main.rs              # таймер старту, цикл подій (poll 120 мс, без бурі пробуджень)
├── buffer.rs            # rope (Ropey) + модель курсора + undo/redo + тести
├── app.rs               # режими, диспетчер, регістри, доповнення, виділення
├── command.rs           # ex-команди + кандидати для попапа ':'
├── keys.rs              # нотація Neovim (<C-s>) + RHS → синтезовані події
├── config.rs            # міні-TOML для теми/опцій
├── lua.rs               # Lua-хост (вендорена Lua 5.1, один процес)
├── explorer.rs          # файлове дерево в сайдбарі
├── highlight.rs         # юнікод-безпечний лексер, 14 мов
├── theme.rs             # палітра Nordic + перевизначення
├── ui.rs                # рендер ratatui, таби, попапи, статус-рядок
└── vimplus_bootstrap.lua # API `vimpp`, доступне юзер-скриптам
```

Правила дизайну: **нуль аллокацій у шляхові рендера**, **нуль блокуючого I/O на клавішах**,
**нуль плагінних процесів** — три речі, які роблять редактори повільними.

## Спробувати редактор

Встановіть Rust і системний C-компілятор, потрібний для вбудованої Lua, потім запустіть:

```sh
cargo run -- src/main.rs
```

Натисніть `F1` або клацніть `[ HELP ]`, щоб побачити всі команди. Для швидкої перевірки: `Ctrl-B` відкриває дерево проєкту, `Enter` відкриває файл, `i` вмикає редагування, `Esc` повертає в Normal, `:w` зберігає. Спробуйте `/fn main`, `n` для пошуку та `:q` для виходу.

## Збірки GitHub і релізи

`.github/workflows/build.yml` збирає програми для Windows і Linux після кожного push. Для публікації файлів оновіть версію в `Cargo.toml`, створіть тег і надішліть його:

```sh
git tag v0.2.0
git push origin v0.2.0
```

Workflow створить GitHub Release з файлами `vimpp-linux-x86_64` та `vimpp-windows-x86_64.exe`. Журнали збірки доступні у вкладці **Actions**.
